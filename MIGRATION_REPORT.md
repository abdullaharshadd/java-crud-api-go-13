### Other review findings
- [warning] **requirement-drift**: The @NotBlank rule on User.name is no longer enforced when a user is updated. The source has spring-boot-starter-validation on the classpath (pom.xml), so Hibernate Validator is active and JPA's default validation mode (auto) re-checks entity constraints before every insert and update. In Java, `PUT /update_user_data/{id}` with a missing or blank name therefore failed: `userDao.save` threw ConstraintViolationException (wrapped in TransactionSystemException), which produced a 500, and nothing was saved. The Go side only calls `User.Validate()` in `Handler.SaveUser`. `Handler.UpdateUser` deliberately skips validation (its comment says the Java method had no @Valid). `userService.UpdateUser`/`save` and the repository's `Update`/`Insert` do not validate either. As a result, an update with a blank or null name now succeeds and writes a NULL or blank user_name, which the original app never allowed at the persistence layer. Suggested fix: call `u.Validate()` in the service's save path, or in the repository before writing, and map a failure to a 500 for parity, or to a 400 if you decide to change that behaviour.
